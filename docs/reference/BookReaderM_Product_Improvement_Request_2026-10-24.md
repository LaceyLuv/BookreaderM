# BookReaderM — 제품 완성도 향상 및 전면 개선 프로젝트

## 0. 역할 및 최종 목표

당신은 BookReaderM 프로젝트의 수석 Android 개발자이자 소프트웨어 아키텍트, UI/UX 디자이너, QA 엔지니어다.

**대상 저장소:** https://github.com/LaceyLuv/BookreaderM

**개발 목표:** 현재 내부 알파 수준인 BookReaderM을 일반 사용자에게 배포할 수 있는 완성도 높은 모바일 전자책 리더로 발전시킨다.

현재 프로젝트는 TXT·EPUB·ZIP/CBZ 읽기, 본문 검색, 북마크, 읽기 위치 저장, 글꼴 변경 등 핵심 엔진 기능을 갖추고 있다.

그러나 사용자 경험이 파일 뷰어 또는 기술 데모 수준에 머무르는 부분이 많다.

이번 프로젝트의 핵심 방향은 다음과 같다.

> **"파일을 열어 읽을 수 있는 앱"에서 "사용자가 자신의 전자책을 체계적으로 관리하고 매일 편리하게 독서하는 완성형 리더"로 발전시킨다.**

기존 기능을 유지하는 수준을 넘어, 실제 독서 앱으로서 필요한 사용성·시각적 완성도·기능성을 종합적으로 개선한다.

기능의 숫자보다 사용자의 체감 품질을 우선한다.

과거 계획서에 미구현으로 표시된 기능이라도 현재 소스에 구현되어 있다면 중복 개발하지 않는다.

## 2. 최우선 과제 — 서재 2.0 전면 개편

현재 BookReaderM의 가장 큰 문제는 서재가 전자책 라이브러리가 아니라 파일 목록처럼 보인다는 점이다.

서재를 실제 독서 앱의 핵심 화면으로 재설계한다.

### 2.1. 서재 화면 디자인

다음 요소를 구현한다.

**상단 영역**

- 앱과 조화되는 서재 헤더
- 검색 버튼
- 책 추가 버튼
- 정렬 및 보기 방식 변경
- 필요할 때만 나타나는 다중 선택·관리 메뉴

**이어읽기 영역**

- 마지막으로 읽은 책의 표지
- 책 제목
- 현재 독서 진행률
- 읽던 위치 정보
- 이어읽기 동작

기존의 '앱 실행 시 서재 진입' 및 'Reader 외부 하단 이어읽기' 계약을 유지한다.

**책 목록**

- 실제 책 표지를 사용하는 그리드
- 제목 및 작가
- 독서 진행률 표시
- 읽는 중 / 완독 / 읽지 않음 상태
- 길게 누르기를 통한 관리 메뉴
- 리스트/그리드 전환
- 가독성 높은 카드 간격과 타이포그래피

개발용 파일 목록 같은 모습이 아니라 완성된 전자책 앱의 시각적 품질을 목표로 한다.

### 2.2. 표지 시스템

파일 형식별로 다음 정책을 적용한다.

**EPUB**

- EPUB 내부 메타데이터에서 표지 추출
- 제목과 작가 정보 추출
- 내장 표지가 없다면 대체 표지 생성

**TXT**

- 책 제목 기반의 자동 표지 생성
- 사용자가 직접 표지를 변경할 수 있는 기능
- 표지 색상 및 스타일 프리셋

**ZIP/CBZ**

- 적절한 이미지 파일을 표지 후보로 추출
- 사용자 지정 표지 지원

표지 생성과 이미지 디코딩은 백그라운드에서 수행한다.

표지 캐시, 메모리 제한, 파일 손상 처리, 데이터베이스 연결을 설계한다.

### 2.3. 책 정보 편집

사용자는 가져온 책의 정보를 직접 수정할 수 있어야 한다.

- 책 제목
- 작가
- 표지
- 읽기 상태
- 분류 및 책장

파일의 원본 내용은 수정하지 않는다.

사용자가 수정한 메타데이터가 나중에 자동 추출 과정에서 덮어써지지 않도록 한다.

### 2.4. 책 관리

다음 기능을 구현한다.

- 최근 읽은 순 정렬
- 추가 날짜순 정렬
- 제목순 정렬
- 작가순 정렬
- 읽지 않음/읽는 중/완독 필터
- 사용자 지정 책장 및 컬렉션
- 여러 책 선택
- 여러 책의 일괄 분류
- 여러 파일 일괄 가져오기

검색 탭의 역할도 재평가한다.

현재처럼 동일한 서재에 단순 검색 필터만 적용하는 구조라면 서재 내부 검색으로 통합하거나, 독립된 검색 화면으로 유지할 만한 충분한 기능을 제공한다.

불필요한 탭을 유지하지 않는다.

## 3. 독서 화면 및 조작 경험 개선

기존 TXT·EPUB·Comic 엔진과 독서 위치 보존 로직을 최대한 재사용한다.

목표는 기능이 많아 보이는 화면이 아니라 실제로 읽기 편한 화면이다.

### 3.1. 독서 도구 UI 재설계

현재 큰 상단·하단 패널과 다수의 텍스트 버튼을 더 직관적인 UI로 개선한다.

- 본문 중앙 탭으로 도구 열기/닫기
- 간결한 상단 제목·뒤로가기 영역
- 하단 진행률 및 위치 이동
- 검색·목차·북마크·글자 설정의 명확한 구분
- 아이콘과 텍스트의 일관된 사용
- 주요 기능은 적은 터치로 접근 가능
- 고급 기능은 별도 설정 화면으로 분리

도구 표시 여부에 따라 본문 레이아웃이나 독서 위치가 변경되지 않아야 한다.

### 3.2. 빠른 독서 설정

다음 항목을 편리하게 조절할 수 있도록 한다.

- 글자 크기
- 줄간격
- 글꼴
- 글자 굵기
- 페이지 여백
- 본문 색상
- 페이지/스크롤 방식
- 페이지 전환 효과
- 화면 밝기

기존에 구현된 설정을 중복 구현하지 않는다.

기본 설정과 책별 설정을 구분하고, 필요하면 독서 프리셋 기능을 추가한다.

### 3.3. 인터페이스 일관성

앱의 서재와 독서 화면이 서로 다른 제품처럼 보이지 않도록 통일된 디자인 시스템을 구축한다.

다음 요소를 일관되게 적용한다.

- 색상 체계
- 글꼴 및 타이포그래피
- 버튼과 아이콘
- 카드와 패널
- 모서리 반경
- 간격 및 그림자
- 애니메이션
- 다크 모드
- 로딩·오류·빈 상태 화면

현재 독서 화면의 장점인 전체화면 활용과 안정적인 읽기 위치 유지는 보존한다.

## 4. TXT 웹소설 특화 기능

한국어 TXT 웹소설을 자주 읽는 사용자에게 유용한 기능을 강화한다.

### 4.1. 자동 목차 생성

TXT 본문에서 다음과 같은 회차 구분 패턴을 인식한다.

- 제1화 / 제2화
- 1화 / 2화
- 제1장 / 제2장
- Chapter 1 / Chapter 2
- 프롤로그 / 에필로그
- 기타 일반적인 회차 제목

자동 감지 결과는 실제 장 제목인지 검증할 수 있어야 한다.

일반 본문에 등장하는 숫자나 문장을 잘못 회차로 판단하지 않도록 한다.

### 4.2. 목차 탐색

- 감지한 회차 목록
- 현재 읽는 회차 강조
- 원하는 회차로 이동
- 잘못 감지된 목차 수정 또는 제외
- 자동 감지가 어려운 경우 수동 목차 지원

목차 생성은 대용량 TXT에서도 독서 화면을 차단하지 않아야 한다.

기존 UTF-16 기반 locator 및 진행도 보존 계약을 유지한다.

## 5. 독서 편의 기능 확장

### 5.1. 형광펜과 메모

TXT·EPUB 본문에서 텍스트를 선택해 다음 기능을 제공한다.

- 형광펜 표시
- 선택한 문장 저장
- 간단한 메모 작성
- 형광펜 색상 선택
- 저장 목록 관리
- 원래 본문 위치로 이동

기존 북마크 기능과 구별한다.

레이아웃 변경이나 앱 재시작 후에도 표시 위치가 유지되어야 한다.

EPUB의 경우 안정적인 텍스트 위치 식별과 기존 Readium locator 구조를 활용한다.

TXT는 기존 정규화된 본문 좌표를 활용한다.

문서 수정이나 버전 차이로 선택 범위를 복원할 수 없으면 잘못된 위치에 표시하지 않는다.

### 5.2. 추가 편의 기능

우선순위와 안정성을 평가해 다음 기능을 단계적으로 검토한다.

- 시스템 TTS 기반 음성 읽기
- 음성 읽기 속도 조절
- 수면 타이머
- 선택한 단어의 사전 조회
- 선택 문장 공유
- 독서 시간과 읽은 책 통계

사용자 계정이나 외부 AI 서비스는 필수 기능으로 추가하지 않는다.

오프라인 독서 기능을 우선한다.

## 6. 데이터 보존과 백업·복원

BookReaderM은 사용자의 책과 독서 기록을 장기적으로 안전하게 관리해야 한다.

### 6.1. 백업 기능

사용자가 직접 백업 파일을 생성할 수 있도록 한다.

백업 대상:

- 책 메타데이터
- 원본 관리 복사본(선택 가능)
- 책장 및 분류
- 독서 위치
- 북마크
- 형광펜과 메모
- 사용자 설정
- 사용자 글꼴(선택 가능)

### 6.2. 복원 기능

- 백업 파일 선택
- 백업 버전 검사
- 데이터 무결성 검사
- 복원 대상 미리보기
- 기존 데이터와 중복 검사
- 기존 데이터 보존 또는 병합 선택
- 실패 시 기존 데이터 보호

백업 포맷은 버전 관리가 가능해야 하며 데이터베이스 마이그레이션과 호환되어야 한다.

원본 파일, 사용자 글꼴, 진행도를 손상시키지 않도록 트랜잭션과 복구 절차를 설계한다.

사용자 허락 없이 외부 서버에 책 또는 백업 데이터를 업로드하지 않는다.

## 7. 현재 확인된 작은 완성도 문제 수정

다음 사항을 실제 코드에서 재확인하고 수정한다.

1. TXT 이외의 책을 가져와도 'TXT를 서재에 추가했습니다'라고 표시할 수 있는 문제
2. 사용할 수 없는 책을 눌렀을 때 사용자에게 원인 안내 없이 동작이 종료될 수 있는 문제
3. 현재 버전의 기능과 오래된 내부 알파 설명이 README에 혼재한 문제
4. 파일명 기반 제목이 사용자에게 그대로 노출되는 문제
5. 책 정보 화면이 지나치게 단순하며 수정 기능이 없는 문제
6. 검색 기능이 별도 탭을 차지할 만큼 충분히 활용되지 않는 문제
7. 화면 전반에 텍스트 버튼과 기술적인 안내 문구가 과도하게 노출되는 문제

확인되지 않은 항목은 재현 없이 버그로 단정하지 않는다.

## 9. 아키텍처 및 구현 원칙

- Android 우선 설계를 유지한다.
- Jetpack Compose 및 기존 KMP 구조를 존중한다.
- 기존 Room 데이터베이스를 무단 초기화하지 않는다.
- 기존 스키마와 데이터의 호환성을 유지한다.
- 스키마 변경 시 명시적 마이그레이션과 테스트를 작성한다.
- 기존 Readium 엔진을 불필요하게 교체하지 않는다.
- TXT·EPUB·Comic의 독서 위치 보존 계약을 유지한다.
- 앱 시작 화면은 서재로 유지한다.
- 이어읽기 기능은 Reader 외부에서 사용할 수 있어야 한다.
- 불필요한 프레임워크나 라이브러리 도입을 피한다.
- 파일과 이미지는 자원 사용량 제한을 적용한다.
- 화면 UI와 저장소·도메인 로직을 적절히 분리한다.
- 새 기능의 상태 저장과 오류 복구를 설계한다.
- 기존 공개 API와 테스트 계약을 함부로 제거하지 않는다.

디자인 개선을 위해 내부 구조를 변경하는 것은 허용하지만, 단순한 코드 미화를 위해 정상 동작하는 핵심 엔진을 전면 재작성하지 않는다.

## 10. 품질 검증 및 완료 기준

각 단계에서 다음 항목을 점검한다.

**기능 검증**

- TXT·EPUB·Comic 정상 열기
- 파일 가져오기 및 삭제
- 책 수정과 재시작 후 유지
- 독서 위치 저장·복원
- 북마크 유지
- 새 기능 동작

**데이터 안전**

- 기존 DB 업그레이드
- 사용자 데이터 보존
- 저장 실패 처리
- 강제 종료 후 복원
- 중복 파일 및 손상 파일 처리

**UI/UX**

- 화면 간 일관성
- 작은 화면과 큰 화면 대응
- 시스템 글자 크기 대응
- 다크 모드
- 접근성
- 터치 및 제스처 충돌 방지
- 로딩 중 입력과 화면 전환

**성능**

- 많은 책이 있는 서재의 스크롤
- 표지 캐시 효율
- 대용량 TXT 열기 및 목차 생성

실제 수행한 테스트와 환경 때문에 수행하지 못한 테스트를 명확히 구분한다.

**각 단계의 완료 조건:** 주요 기능 구현, 사용자 시나리오 검증, 기존 기능 회귀 확인, 문서 갱신, 미해결 문제 보고.

## 11. 작업 진행 방식

첫 단계는 전체 감사를 수행해 구현 상태와 우선순위를 확정하는 것이다.

그다음 Phase 1부터 순서대로 실제 구현한다.

다음 규칙을 따른다.

1. 최신 저장소 상태를 우선 확인한다.
2. 기존 작업과 사용자 변경을 보존한다.
3. 기능별로 구현 단위를 나눈다.
4. 각 작업에 필요한 테스트를 작성한다.
5. 검증이 끝난 단위를 논리적인 커밋으로 기록한다.
6. 중간 실패와 미실행 검증도 숨기지 않는다.
7. 기능 완료 후 다음 우선순위 작업으로 진행한다.
8. 대규모 작업이므로 단계별 결과와 미완료 항목을 명확하게 남긴다.

진행 중 필요한 세부 디자인·내부 기술 선택은 제품 목표에 맞게 자율적으로 결정한다.

단, 다음 작업은 별도 사용자 승인을 받는다.

- 사용자 데이터 삭제
- 파괴적인 저장소 변경
- 기존 서명키 교체
- 공개 릴리스 게시
- 외부 서비스 계정 및 유료 서비스 연동
- 실제 사용자 데이터의 외부 전송

별도 승인이 필요한 작업에 도달하면 나머지 안전한 개발 작업은 계속할 수 있다.

문서만 작성하고 구현을 완료한 것처럼 보고하지 않는다.

## 13. 가장 중요한 최종 지침

이번 작업의 목적은 기능 목록을 무작정 늘리거나 코드 규모를 키우는 것이 아니다.

**BookReaderM이 더 이상 초기 개발용 데모처럼 느껴지지 않도록 만드는 것이다.**

서재를 열었을 때 깔끔하게 정리된 책들이 보이고, 읽던 책을 쉽게 찾을 수 있으며, 책을 읽고 관리하는 모든 과정이 자연스럽고 편리해야 한다.

핵심 엔진의 안정성과 데이터 안전성을 유지하면서 제품 디자인, 사용성, 편의 기능을 균형 있게 발전시킨다.

특히 서재 2.0을 최우선 목표로 삼는다.
