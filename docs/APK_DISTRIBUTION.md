# APK 배포·다운로드 운영 방안

사용자는 GPT Android 앱의 파일 미리보기가 20MB 이상을 지원하지 않아 기존 APK 링크를 열지 못했다고 확인했다(2026-10-24).
설치 패키지 오류와 다운로드 미리보기 제한을 구분한다. APK가 커져도 같은 문제가 반복되지 않도록 아래 방식을 사용한다.

## 기본 전달 경로

검증된 설치용 APK를 GitHub Releases의 버전별 시험용 릴리스에 첨부하고 대화에는 **HTTPS 다운로드 페이지 링크**를 안내한다.
사용자는 Chrome 등 외부 브라우저에서 페이지의 Assets를 열어 APK를 다운로드한다.
`/workspace/...apk` 미리보기 링크를 최종 다운로드 수단으로 안내하지 않는다.
ZIP 압축·분할은 임시 보조 수단이며 크기 제한에 대한 장기 해법으로 삼지 않는다.

## 배포 순서와 자동화 목표

1. 버전과 소스 commit을 고정하고 필수 빌드·단위·기기·복원 검증을 실행한다.
2. 모든 필수 검증이 성공한 소스에서 APK를 생성하고 기존 인증서로 서명한다.
3. 서명 필수 APK 감사, versionCode 증가, 기존 인증서 일치, SHA-256을 확인한다.
4. 버전별 릴리스 초안에 APK·체크섬·변경 내용을 첨부한다. unsigned APK/AAB는 설치 파일로 안내하지 않는다.
5. 업로드한 파일을 다시 내려받아 크기와 SHA-256을 대조하고 다운로드 경로를 확인한다.
6. 합의된 공개 범위 내에서 시험용 prerelease를 게시하고 해당 버전 페이지를 안내한다.

향후 CI 자동화는 이 순서를 따르며 실패한 빌드를 업로드·게시하지 않는다.
서명키·비밀번호는 저장소, 로그, APK 첨부물에 넣지 않는다. 보호된 CI secret/파일로 공급하고 기존 키를 임의 교체하지 않는다.
기존 앱을 삭제하지 않는 업데이트를 위해 같은 applicationId·서명 인증서를 유지하고 versionCode를 올린다.

## 공개 범위와 현재 상태

현재 LaceyLuv/BookreaderM은 공개 저장소다. 여기에 게시한 릴리스 APK도 공개된다.
개인 배포가 필요하면 비공개 배포 저장소와 로그인 기반 다운로드를 사용한다.
자동 공개 범위/자격증명을 구성하기 전에는 문서화나 초안 생성을 공개 출시 완료로 취급하지 않는다.

2026-10-24 현재 자동 서명·Releases 배포 workflow는 **구현 전 계획**이다.
0.4.0 릴리스 초안 ID 422430819는 업로드 대기 상태이며 첨부 파일은 없다.
`uploads.github.com` 연결은 HTTP CONNECT 403으로 차단됐다. 기존 설정을 보존한 네트워크 허용 초안은 저장됐으나
환경 설정에서 사용자 저장·게시가 필요하다. 설정 적용 후 GitHub API/업로드 권한과 실제 다운로드를 재검증한다.
관련 목적지는 `api.github.com`, `uploads.github.com`, `github.com`, `release-assets.githubusercontent.com`이다.
확인하지 않은 링크를 다운로드 가능하다고 안내하지 않는다.
