# ADR0012 — 독서 기록의 수동 백업과 추가 방식 복원

2026-11-21. Phase 4의 첫 단위다. 제품 개발 지침 §6과 구현 계획 §28의 수동 백업·복원을
독서 기록부터 구현한다. 책 원본과 사용자 글꼴·표지 파일을 선택적으로 함께 패키징하는
작업은 파일 커밋과 중단 복구를 포함하는 다음 단위다.

## 파일 형식

설정의 **독서 기록 백업·복원**에서 시스템 파일 선택기로 저장 위치나 기존 파일을 고른다.
파일명 기본값은 `BookReaderM-독서기록.brmbackup`이다. 이름이나 제공자 MIME만으로 형식을
판정하지 않는다. 외부에서 받은 파일을 앱 시작이나 책 가져오기 때 자동으로 복원하지 않는다.

v1은 압축하지 않은 단일 UTF-8 JSON 기록과 48바이트 헤더로 구성된다.

| 순서 | 필드 | 크기 |
|---|---|---:|
| 1 | ASCII `BRMBKUP`와 LF | 8바이트 |
| 2 | 빅엔디언 형식 버전 | 4바이트 |
| 3 | 빅엔디언 JSON 바이트 수 | 4바이트 |
| 4 | JSON SHA-256 원시 다이제스트 | 32바이트 |
| 5 | UTF-8 JSON | 최대 8 MiB |

가져오기와 내보내기 모두 동일 v1 타입과 한도를 사용한다. 삭제 중인 책을 제외하고
Room의 단일 읽기 트랜잭션에서 허용된 열을 가져온다. DB 값을 힙으로 옮기기 전에
BLOB 바이트 수, 책 최대 2,000권, 전체 행 최대 20,000개를 검사한다. 파일은 JSON 바이트 수,
끝 위치, SHA-256, UTF-8, 구조와 도메인 규칙을 검사한다. 미래 버전, 손상, 한도 초과는
적용 전에 거부한다. 해시는 무결성 검사다. 백업에 선택한 문장과 메모가 평문으로 들어가므로
사용자가 저장 위치와 공유 여부를 관리한다.

책 서지 정보와 원본 지문, 현재 해석 및 이전 TXT 인코딩별 기록, 진행도, 북마크,
형광펜·메모, TXT 목차 수정, 책장과 분류, 서재 표시 기본값, Reader 전체·책별 설정을 담는다.
책 원본 바이트·글꼴 파일·표지 이미지·앱 테마·앱 DB 파일·캐시·URI·사용자 저장 경로·서명키·
쓰기 세션 번호는 포함하지 않는다. Reader 설정의 사용자 글꼴 ID는 함께 보존되며 글꼴
파일을 확인할 수 없을 때 기존 기본 글꼴 대체 정책을 따른다. OS 자동 백업 정책은 유지한다.

## 복원

1. 선택한 파일을 제한된 메모리에서 검증하고, 원본 SHA-256과 바이트 수로 같은 책을 찾는다.
   확인 화면에서 새 책, 같은 원본, 형식 충돌이나 삭제 중인 항목, 기록 수를 보여 준다.
   미리보기 뒤 제공자의 파일이 변경되더라도 이미 검증한 데이터만 적용한다.
2. **새 책 기록만 복원**과 **기존 책에도 없는 기록 추가** 중 하나를 선택한다.
   낮은 위험의 기본값은 새 책이다. 같은 원본의 기존 책을 병합하면 형식이 일치해야 한다.
   현재 인코딩·제목·표지·기존 진행도와 동일 키의 기록을 보존한다. 기존 설정은 보존하고
   빠진 설정만 추가한다. 책장은 이름으로 대조하며, 분류는 일반 서재와 같은 최대치를 적용한다.
3. 원본이 없는 책은 새로운 UUID를 가진 `MISSING` 행으로 복원한다. 파일은 쓰지 않는다.
   사용자가 책 추가에서 동일한 원본을 선택하면 기존 관리 복사본 가져오기 경로가
   파일 바이트를 검증하고 복원한 책에 연결한다. 저장 위치는 앱이 UUID로 결정한다.
   비슷한 제목이나 쪽수로 책이나 위치를 추측하지 않는다.
4. 가져오기·삭제와 같은 관리 작업 잠금을 잡고 즉시 쓰기 트랜잭션에서 대상의
   ID·revision·가용성을 다시 확인한다. 책의 대응이 바뀌면 파일을 다시 열도록 안내한다.
   해당 트랜잭션은 누락 행만 추가한다. 합쳐진 기록이 원래의 보관 한도를 넘거나
   어느 SQL 단계가 실패하면 이번 복원 전체가 롤백된다. 재시도해도 기존 값이나
   쓰기 epoch를 갱신하지 않는다. 실제 독서를 시작할 때만 기존 경로가 새 세션을 연다.

Room 스키마는 9 그대로다. 기존 1→9 마이그레이션 뒤 같은 형식으로 내보낸다.
DB 파일 자체나 다른 기기의 WAL을 복사하거나 교체하지 않는다. 화면을 재생성해도 진행 중인
미리보기는 ViewModel에 남는다. 프로세스 종료 전 저장 완료가 확인되지 않은 외부 파일은
바이트 수와 SHA-256 실패로 검출할 수 있다. 외부 DocumentsProvider의 저장·동기화 방식은
해당 제공자가 결정한다.

## 검증 계약

JVM Room은 새 DB 재개방, TXT 이전 해석과 EPUB/Comic locator, 새 책 모드와 추가 병합 모드,
반복 복원, 트리거로 중단시킨 트랜잭션, 보관 한도, 미래·과대 행 보존을 검사한다.
파일 검사에서는 버전, 길이, SHA-256, 잘린/덧붙인/변조된 파일 및 다시 계산된 해시 뒤의
잘못된 데이터도 검사한다. Android는 실제 Activity 결과와 별도 UID 테스트 제공자의
URI 권한, 백업 화면, 미리보기 뒤 제공자 내용 변경, 손상 거부, 동일 원본 다시 연결과
독서 위치 복원을 검사한다. 시스템 파일 선택기의 실제 UI와 외부 제공자별 호환성 범위는
기기 결과에서 구분한다.
