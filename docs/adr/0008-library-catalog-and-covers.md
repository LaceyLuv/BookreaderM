# ADR 0008 — 서재 메타데이터·표지·책장

상태: Phase 2 구현 중, 2026-10-24. [사용자 지침](../reference/BookReaderM_Product_Improvement_Request_2026-10-24.md).

기존 Book의 title/author/coverKey를 사용하고 원본·locator·writer epoch 필드는 변경하지 않는다.
Room5→6은 사용자 편집 우선권/읽기 상태/표지 프리셋, 책장, 다대다 연결, 서재 보기 설정의 별도 테이블만 추가한다.
사용자 편집과 자동 추출은 같은 DB writer transaction 안에서 현재 편집 비트를 다시 읽는다.
늦은 추출이 편집을 덮어쓰거나 삭제된 책을 재생성할 수 없다. 일괄 분류는 전체 성공/롤백이다.
책장 삭제는 연결만 지우며 책·진행도는 유지한다. 자동 상태는 현재 revision의 진행도와 읽기 이력에서 계산하고
사용자가 지정한 읽기 상태를 우선한다. 완독 표시는 Reader의 locator나 진행도를 변경하지 않는다.

표지는 관리 원본에서 생성하는 파생 캐시와 사용자 지정 영구 복사본을 구분한다.
키는 `a-<SHA256>.jpg` 또는 `u-<SHA256>.jpg`이며 경로/URI를 허용하지 않는다.
자동 표지 디스크 캐시128MiB, 메모리8MiB를 적용한다. 사용자 표지는 별도 영구 영역128MiB 한도이며
용량 부족 때 기존 사용자 표지를 임의 삭제하지 않는다. 사용하지 않는 사용자 표지는 취소된 편집과 경합하지 않도록
24시간 유예 후 DB 참조를 확인하여 정리한다. 원본 책·원본 이미지에는 쓰지 않는다.

EPUB는 고정 Readium3.1.2의 실제 Publication.metadata.title/authors·linkWithRel API와 SafeEpub 검증 경로를 사용한다.
Comic은 기존 manifest/decoder에서 처음 읽을 수 있는 이미지 후보를 사용한다. TXT나 실패한 추출은 제목/작가 프리셋 표지다.
사용자 이미지와 EPUB 표지는 IO에서 직렬화하고 입력8MiB, 임시 bitmap8MiB 미만, JPEG384×576/768KiB 이하로 제한한다.
Comic은 기존 decoder의 엔트리64MiB 제한과 별도 bitmap8MiB budget을 적용하고 처음8개 후보까지만 검사한다.
표지와 메타데이터 오류는 독서 엔진이나 마지막 진행도를 변경하지 않는다. 화면에서 보이는 책의 표지와 별도로 EPUB 메타데이터를 서재 소유 순차 코루틴에서 처리하여
화면 밖 책도 제목/작가 검색에 포함한다. 같은 직렬 decoder 경로를 사용하고 Reader 진입 시 취소한다.

검증: 이전1–5 스키마 업그레이드/실패 롤백, 재시작 유지, 늦은 추출/편집 경합, 분류 롤백,
포맷별 실제 추출·디코드/손상 입력/자원 한도, 실제 서재 UI와 전체 Reader 회귀를 각각 실행해 기록한다.
이 문서는 구현·검증 완료 표시가 아니며 결과는 TASKS/WORKLOG를 따른다.

일괄 가져오기는 명시적 picker의 content grant만 최대64개 받아 기존 journal 기반 importer를 순차 호출한다.
VIEW/SHARE는 기존 단일 URI 검증을 유지한다. 개별 파일 오류는 계속 처리하고 저장 공간/DB 오류는 중단한다.
취소되더라도 이미 commit된 책을 유지한다. private preference의 active marker는 시작 전에 동기 저장하고
정상 종료/취소 정리가 끝난 뒤 해제한다. 프로세스 종료 후 기존 journal을 복구하고 완료된 책 보존 및
남은 파일 재선택을 안내한다. 임시 URI 권한을 영구 권한처럼 추정하거나 입력 URI 목록을 로그에 남기지 않는다.
